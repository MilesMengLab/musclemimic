# 求解器、安装贴合和终端显示验证

2026-11-04 的修复将 `MjxMyoFullBodyHumanExo` 接入官方 `MjxMyoFullBody` 的协作继承链。此前仅设置 `mjx_enabled=True`，没有运行官方 GPU 构造函数，保留 XML 中 `iterations=100`、`ls_iterations=50`。现在默认使用 `iterations=4`、`ls_iterations=8`，并关闭 `EULERDAMP`，与官方初始化一致。用户显式传入的求解器配置仍优先。运行时配置转为普通字典，允许上游补入 timestep 等字段。

实际求解器参数写入实验配置。新 checkpoint 的 CPU 播放会继承同一数值设置；静态安装预览只执行前向计算。减小迭代上限会影响数值精度，短测试通过不能替代长期闭环负载与助力验证。

终端表格按 SB3 的分组、字段字母顺序、3 位有效数字和列宽规则打印，不带 Hydra 时间戳前缀。动态进度条采用 MyoAssist/SB3 所用的 Rich 列：百分比、伸缩横条、步数、已用时间、剩余时间及 it/s。通过伪终端验证 ANSI 原地刷新，表格在进度条上方输出。非交互文件输出保留表格和结束时的进度行，不写刷新控制序列。

进度按 JAX 每轮 rollout 回调更新，刷新已用时间持续进行。原 SB3 逐环境步回调与批量 JAX 回调的更新粒度不同；表格只输出真实 PPO 指标，不添加该算法不存在的 KL 提前终止或镜像损失日志。程序正常结束、异常和中断均会关闭进度显示，避免退出时残留 Rich 资源。

纯表格另存 `training_console.log`，原始指标及累计/逐轮耗时、FPS 存 `training_metrics.jsonl`。表格 FPS 延续累计口径，包含编译开销；吞吐比较使用排除前四次更新后的采样步数除以这些更新总耗时。

准备阶段显示“初始化 / 编译中”。进度条由首个非零训练更新回调启动，参数数量和零步数消息不启动进度条。中断初始化不会输出空的零步进度条。续训首轮按 checkpoint 的累计步数显示，JSONL 保留原累计耗时和首轮有效步数的统计。

同一新安装模型上，两组 32 环境、64 步 rollout、32768 总步、默认网络和 PPO 参数、关闭验证的顺序短基准：旧设置约 933 步/秒，官方设置约 1033 步/秒，约提升 11%。该结果表明，修复默认参数本身没有带来数量级加速，进一步扩展并行规模需要实测。输出位于忽略目录 `generated/solver_comparison/`。上述结果是 PPO 整轮吞吐，包含采样、更新与日志，不是独立仿真内核速度。

安装调整将电机沿共同膝轴从 56 mm 偏置向内靠近 1 mm，当前为 55 mm。上合页补偿为 -7 度，下合页约 -0.257684 度。小腿全体部件的最近骨骼间隙为 3 mm，骨骼网格无交叉；上端肌肉显示重叠约 0.327 mm，在用户允许的 0.5 mm 内。轴线夹角小于 0.0001 度、轴线距离接近零。URDF、网格和机构连接关系未修改。

19 项框架测试覆盖官方求解器继承、显式参数覆盖、动态进度生命周期、表格输出和原始指标保存，以及真实安装与网络接口。新参数训练、保存和两步 CPU 播放通过。完整 CI 结果及更大批量吞吐在后续实测条目补充。

同样设置扩展到 128 环境、65536 总步后，8 次更新完成，排除前四次后的整轮吞吐约 3049 步/秒，是旧 32 环境约 3.27 倍、修复后 32 环境约 2.95 倍。32 环境比较每组测量 12 次更新，128 环境测量 4 次更新，样本较短且动作批量不同，不保证长训练始终维持此倍率。此项改变每轮采样批量，可能影响学习曲线，不能只按总步数假定相同收敛结果。

三组 PPO 指标有限，模型保存通过。仅执行以上短基准，没有启动 3000 万步训练。需要使用已测的 128 环境配置可执行：

```bash
./scripts/hum_exo.sh train device=knee_exo experiment.env_params.num_envs=128
```

完整 CI 通过 490 项，25 项跳过、15 项按仓库规则排除。Ruff 和 `git diff --check` 通过。
